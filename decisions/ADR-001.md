# ADR-001: Faithfulness evaluator — claim decomposition + judge validation

**Status:** Accepted (implementation scaffold landed; κ on full ~75-case set still pending)  
**Sprint:** 01-faithfulness  
**Date:** 2026-07-28  
**Deciders:** Saran

## Context

We need a reference-free faithfulness score for RAG answers grounded in property/listing documents. Off-the-shelf RAGAS gives a useful shape (decompose → verify → `|V|/|S|`) but:

1. Raw agreement with humans overstates discriminative ability (see *Reliability without Validity*, arXiv:2606.19544).
2. Decomposition quality dominates the score — coarse claims hide partial hallucinations.
3. We need a uniform cost/latency schema (`costmeter`) from day one for later cross-sprint comparison.

## Decision drivers

- Headline metric must be **chance-corrected** (Cohen's κ), not exact match.
- Atomic claim decomposition is built **unassisted** this sprint (skill boundary).
- Domain test set (~75–100 cases) beats WikiEval transfer for listing/voice use cases.
- Spec and numeric criteria exist **before** implementation.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| A. Use RAGAS library as-is | Fast | Opaque decomposition; hard to diagnose; no κ discipline |
| B. Reimplement faithfulness from scratch + audit | Full control; teachable; MVVP-compatible | More build time |
| C. FActScore against Wikipedia | Strong atomicity | Wrong knowledge source for RAG; not context-faithfulness |

**Chosen:** B — reimplement RAGAS-shaped faithfulness; borrow FActScore atomicity discipline; validate judge with MVVP-lite.

## Decision

1. **Pipeline:** answer → atomic claims → per-claim support vs retrieved context → score = supported / total.
2. **Human labels:** ~75–100 cases across: fully supported · partially supported · contradictory · correct-but-unsupported · poor-retrieval · wrong price/feature · facts merged across properties · (optional) empty retrieval.
3. **Headline metric:** Cohen's κ between evaluator binary support labels and human labels. Report raw agreement only as secondary.
4. **Judge audit (MVVP-lite):** κ; ≥3 replicates at temperature 0 with cache disabled; adapted position/order bias check for Yes/No claim verification; document paradox if high stability + high bias.
5. **Comparison:** same cases through RAGAS faithfulness for a delta table.
6. **Instrumentation:** `costmeter` v1 with OpenTelemetry GenAI conventions; every eval records tokens, $, latency.

## Numeric success criteria

| Criterion | Target |
|---|---|
| Labelled cases | ≥ 75 |
| Cohen's κ vs human (claim-level or answer-level — pick in results and stick) | Report honestly; post if κ gap vs raw agree is material |
| Cost per evaluation | Measured and in README results table |
| p50 / p95 eval latency | Measured |
| Regression test | Fails if a known-hallucinated fixture scores as fully faithful |

## Consequences

- Positive: auditable evaluator; foundation for `evalkit`; capstone cost comparisons possible.
- Negative: slower than `pip install ragas`; must maintain prompts.
- Follow-ups: answer/context relevance deferred; SelfCheckGPT as offcut only.

## Revisit if

- κ remains near chance after prompt iteration → change decomposition unit or verification model.
- Domain labels too noisy (IAA too low) → shrink label taxonomy before more cases.
- Cost blows latency budget for CI → cascade / cheaper verifier for regression only.
